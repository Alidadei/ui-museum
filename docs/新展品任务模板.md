# 新展品任务模板

> **用法**：新开一个会话（agent 没有任何上下文），把下面分割线内的整段话复制给它，
> 只需要改【这次的任务】里的创作简报。馆内约定都写在仓库里
> （`README.md`、`registry.js` 头部注释、`docs/eli5.html`），agent 自己会读，不用再解释原理。

---

【项目】`R:\Code\MY project\ui-museum\` —— 我的「界面收藏馆」，收录我做的和喜欢的 UI。每套 UI 独立隔离，加展品 = 盖房 + 挂号。

【先读】动手前先看 `README.md` 的「如何收录一套新 UI」和 `registry.js` 头部的字段注释，严格遵守馆内约定。

【这次的任务】为我 vibe 一件新展品：
　<创作简报：主题 / 风格 / 交互 / 想要的情绪，越具体越好>

【硬规矩】零构建零安装：不用 npm/框架/打包器，手写优先（CSS 动画、Canvas 足够覆盖大多数动效）。确需第三方库（three.js / GSAP / Lottie 等）时，把库文件下载进 `uis/<slug>/vendor/` 本地引入，跨展品复用的放 `shared/<名字>/`；**禁止 CDN 外链**（国内加载不稳）。整套自包含放 `uis/<英文slug>/`；资源一律相对路径；完成后在 `registry.js` 照 №001 的字段格式登记，本地起服务验证「缩览 + 步入全屏 + Esc 归馆」都正常，git commit + push 上线。

## 创作简报怎么写

简报是这段话术的灵魂——新 agent 不了解你的口味，所以**想要什么、不想要什么都要直说**。

- 差：「做一个好看的登录页。」
- 好：「一个『深海潜航』主题仪表盘：深蓝荧光风；深度数字随滚动变化；开场 2 秒下潜动画要有仪式感；**别做成常见 SaaS 后台样式**。」

## 想改馆本身（而不是加展品）时

把【这次的任务】换成要改的总台功能（配色 / 交互 / 布局），其余段落原样保留；
改动保持零依赖纯静态，改完同样本地验证 + 推送。

## 备注（本机环境）

- 本地预览：在 `ui-museum/` 目录起任意静态服务（如 `python -m http.server 8123`）。
- `git push` 依赖本机代理 `127.0.0.1:7890`；报 Connection refused 是代理没就绪，等一会原样重试（直连会超时，不要绕过代理）。
